# DansTV on Samsung Q80T — Windows setup

**Status:** the owner has signed the independent DansTV widget, passed 16 device tests and 452 browser checks, and begun first-hardware launch. Feature and responsiveness verification on the actual Q80T remains ongoing.

## Safety

This first milestone only prepares, signs, installs and launches a separately identified web application. It does not alter firmware, Samsung Home, startup, system apps, service settings, or native key assignments. Never run the Frame 2020 native Home helper unmodified on a Q80T. Keep Samsung Home accessible.

## Prerequisites

- Windows 10/11, Python 3.10+, Node.js 22.13+ or 24+, Samsung Tizen Studio TV SDK/SDB and Samsung Certificate Extension.
- A Samsung account and your own Certificate Manager profile, including your Q80T DUID in the distributor certificate.
- TV and PC on the same trusted network.
- PowerShell 5.1+ or 7; do not commit local addresses, DUIDs, certificates or passwords.

## 1. Preview and static checks (offline from TV)

    npm ci
    npm run win:check
    npm run win:preview

Visit http://127.0.0.1:4795/home/. This is a desktop preview, not a TV compatibility test.

## 2. Configure your own identity

Generate a separate 10-character package ID and application ID through the official Samsung project tools, and create your own certificate profile. Set ignored .local/signing.json to:

    {
      "sdk_path": "C:\\tizen-studio",
      "profile": "DansTV",
      "package_id": "AbCdEf1234",
      "app_id": "AbCdEf1234.DansTV",
      "password_file": null
    }

All values above are examples. Use an identity generated by your SDK, not the maintainer's existing identity. Keep your own app identity and author certificate stable for in-place updates. The packaging step changes the generated widget identity, not tracked app/config.xml.

    python scripts/owner-widget.py --check

## 3. Sign on Windows

    .\scripts\q80t-windows.ps1 Sign

This prepares an unsigned owner widget, signs through the official Samsung CLI and checks signature files, manifest identity and private-file exclusions. It does not verify cryptographic chains or install anything on the TV. Use saved Certificate Manager access; do not pass passwords on the command line. The Windows workflow is newly added and requires local validation.

## 4. Read-only TV capability check

Find model and full firmware in Settings → Support → About This TV. In Apps → App Settings, enter 12345 with the remote number pad, enable Developer Mode and set Host PC IP to your Windows PC's LAN IP. Restart when prompted. Find the TV's own IPv4 address in TV Network Status.

Create ignored .local/device.json with your TV's actual IP (example only):

    {"host": "192.168.1.50"}

Then run:

    .\scripts\q80t-windows.ps1 Info

This connects the developer tools and runs a read-only capability query. Stop if the device, firmware or transport is unexpected.

## 5. Explicit installation and launch

Only when ready to install a new app:

    .\scripts\q80t-windows.ps1 Install
    .\scripts\q80t-windows.ps1 Launch

Confirm visible result on the TV: correct navigation, installed apps, HDMI selection, saved preferences, remote Back, and Samsung Home access. Check normal power-on remains unchanged. Do not interpret SDK success as proof all these flows work.

## Privacy and performance limits

Run python scripts/check-offline.py: it scans bundled JavaScript, HTML and CSS for common network APIs/external resources and checks the manifest for Internet privileges. This is a regression check, not a runtime firewall. It cannot block Samsung OS telemetry or requests made by Netflix, YouTube or other launched apps. Capture actual network traffic separately with your router, DNS resolver or firewall; block domains selectively and test streaming and firmware behavior. No claim of complete privacy can be made from app source alone.

Browser performance checks are not Q80T performance benchmarks. Measure responsiveness and memory on the actual TV before removing features.

## Tizen 5.5 Home takeover and debloating

The optional [tiz0wn integration](../scripts/tiz0wn/README.md) now contains a Windows read-only Q80T preflight, root-side CPU/RAM and package snapshot, and a separately staged Home-key database remap plus exact-value restore. It adapts the Tizen 5.5 `tvctx-manager`/`.app-context.db` approach measured on another 2020 TV. **None of these are installed or proven on the Q80T yet.** The existing reference-Frame native helper has different guards and must not be reused unmodified. Full firmware identification, a validated root transport, off-TV database backup, explicit write and restore trial precede a permanent takeover. For debloating, use the audited upstream `pkgstate` plan/enable/disable tools one candidate at a time rather than deleting unknown packages.
